# 新增「操作快照」与「系统日志」两个桌面模块

## Context（为什么做）

面板目前已有两类历史能力，但都不好用：

1. **变更前的快照被埋起来了**。环境管理在每次变更（装/升级/卸载/换源/env 变量）前都会采集一份快照，落在 `data/host-N/snapshots/op-N/`（`packages.tsv` + `sources.tgz`，见 [snapshot.go](file:///media/yunxi/FE73-D3B5/Panel%20SSH/internal/env/snapshot.go#L58-L94)），但没有独立入口，只能在「环境管理 → 操作记录」页签里按**单台主机**翻看，而且快照内容（包里到底装了什么）在界面上完全看不到。用户要跨主机回看"我最近改过什么、当时是什么状态、能不能退回去"，现在做不到。

2. **目标机的系统日志面板完全没有入口**，排障得自己开终端敲 journalctl / tail。面板自身的运行日志更是没有落盘，进程一退就查不到死因。

本次新增两个内置桌面应用解决这两件事：**操作快照**（跨主机汇总已有变更快照 + 查看内容 + 与上一次对比 + 回滚）与**系统日志**（journalctl / `/var/log` 文件 / dmesg / 面板自身日志，只读查看 + 过滤 + 自动刷新）。

## 已确认的关键决策

| 决策点 | 结论 |
| --- | --- |
| 「操作快照」的定位 | 汇总已有变更快照（不新建通用快照机制） |
| 快照文件存放 | 面板本地数据目录 `data/host-N/snapshots/op-N`（沿用现状，不改） |
| 对比能力 | 选中一条快照，自动与**同主机上一条**快照做包差异（纯本地计算，不连目标机） |
| 系统日志来源 | journalctl + `/var/log` 常见文件 + dmesg + 面板自身日志，四者都要 |
| 系统日志能力 | 只读查看 + 过滤 + 自动刷新（不做导出、不做清理） |
| 面板自身日志落地 | 落盘到 `data/panelssh.log`（启动时超过 5 MB 轮转为 `.1`），不改部署方式 |
| 环境管理的「操作记录」页签 | **保留**（单机顺手入口），新窗口做跨机总览，共享同一份后端数据 |

## 模块一：操作快照

### 后端

**新增 `internal/api/snapshots.go`**，两条路由注册到 [server.go](file:///media/yunxi/FE73-D3B5/Panel%20SSH/internal/api/server.go#L277-L279) 环境管理那一段之后：

```
GET /api/snapshots            → handleSnapshotList
GET /api/snapshots/{opId}     → handleSnapshotDetail
```

1. `handleSnapshotList`：`store.ListEnvOps(-1, 200)` 取全部主机操作，逐条补快照落盘信息 —— 注意 `EnvOp.SnapshotDir` 带 `json:"-"`（[store/env.go](file:///media/yunxi/FE73-D3B5/Panel%20SSH/internal/store/env.go#L56)），因此**新建一个视图结构 `snapshotView`** 组装后再序列化，不要改 EnvOp 的 json tag：
   - `hasSnapshot`：目录存在（`os.Stat`）
   - `snapshotBytes`：目录内 `packages.tsv` + `sources.tgz` 大小之和
   - `packageCount`：`packages.tsv` 行数（`snapshotDir` 为空或目录已清理时给 0）
   - `pruned`：操作已结束（`status != running`）但目录不存在 ⇒ 快照已被 `pruneSnapshots` 的**保留 20 条**策略清掉（[operation.go](file:///media/yunxi/FE73-D3B5/Panel%20SSH/internal/env/operation.go#L17-L44)）。界面必须把这件事说出来，否则用户会以为面板丢了数据。

2. `handleSnapshotDetail`：`store.GetEnvOp(opId)` → 目录不存在则返回 `{ available: false, reason: "快照已按保留策略清理（每台主机保留最近 20 次）" }`；存在则：
   - 取包管理器：`s.hostProfile(ctx, op.HostID, false)`（有缓存）+ `env.NewManager(profile)`；**目标机连不上或主机已删除时降级**为返回 `packages.tsv` 原始文本（`parsed: false`），保证历史永远可读。
   - `env.LoadSnapshot(dir, mgr)` 得到结构化包清单（name/version/arch）+ Facts；`sources.tgz` 是否存在与字节数。
   - **与上一次快照对比**：`store.ListEnvOps(op.HostID, 100)` 中找 `id < op.ID` 且快照目录存在的最近一条，读取其 `packages.tsv` 用同一个 `mgr` 解析，计算 `added` / `removed` / `changed`（同包名版本不同），返回 `diff: { baseOpId, added, removed, changed }`；找不到基准则 `diff: null`。

**不新增回滚后端**：回滚继续走已有的 `POST /api/hosts/{id}/env/plan` + `GET /api/ws/env`。

### 前端

- **新增 `web/src/windows/SnapshotWindow.vue`**（master-detail，只读 + 回滚入口）：
  - 左：跨主机操作列表（时间、主机、动作、目标、状态、快照标记）。顶部工具条：主机筛选（全部 / 某台）、动作筛选、刷新。列表项状态 LED 与文案复用 EnvManager 里 `opStatusType` / `opStatusLabel` 的写法。

## 模块二：系统日志

### 后端

**1. 面板自身日志落盘（新机制，改动很小）**

- `internal/config`：加常量 `LogName = "panelssh.log"`。
- [cmd/panelssh/main.go](file:///media/yunxi/FE73-D3B5/Panel%20SSH/cmd/panelssh/main.go#L32-L48)：在 `log.Fatalf` 之前打开 `filepath.Join(cfg.DataDir, config.LogName)`，若已存在且 > 5 MB 先 `os.Rename` 为 `.1`（覆盖旧 `.1`），然后 `log.SetOutput(io.MultiWriter(os.Stdout, f))`。这样 stdout 行为不变，重启后仍能回看上一次的启动/崩溃现场。

**2. 新增 `internal/sysinfo/logs.go`（命令构造 + 解析，纯函数，便于单测）**

- `LogSourcesScript()`：一次 SSH 拿回两个分节 ——
  - `###JOURNAL`：`command -v journalctl` 是否存在
  - `###FILES`：候选日志文件的 `stat -c '%s\t%Y\t%n'`。候选路径**由后端生成固定白名单**（`/var/log/{syslog,messages,auth.log,secure,kern.log,user.log,boot.log,dpkg.log,yum.log,dnf.log,cron,cron.log,maillog,nginx/access.log,nginx/error.log,apache2/access.log,apache2/error.log,mysql/error.log}`）再补一层 `/var/log/*.log` 通配，逐个 `[ -f "$f" ] && stat -c ...`。
    不使用 `find -printf`（busybox find 不支持，与 [snapshot.go 里对 busybox tar 的顾虑](file:///media/yunxi/FE73-D3B5/Panel%20SSH/internal/env/snapshot.go#L26-L29) 同理）。
- `LogCommand(source, file string, unit, priority string, lines int) string`：
  - `journal`：`journalctl -n <lines> --no-pager -o short-iso [-u <unit>] [-p <priority>] 2>&1`
  - `file`：`tail -n <lines> -- <file> 2>&1`
  - `dmesg`：`dmesg 2>&1 | tail -n <lines>`
- 参数校验函数 `ValidateLogQuery(...)`：`lines` 限 1–2000；`file` 必须匹配 `^/var/log/[A-Za-z0-9._/-]+$` 且不含 `..` **且出现在 sources 清单里**（防路径穿越与任意读）；`unit` 匹配 `^[A-Za-z0-9@._:-]+$`；`priority` 限白名单（`0-7` 或 `emerg/alert/crit/err/warning/notice/info/debug`）。校验失败一律 400，**不做"失败再试一次"的兜底**。

**3. 新增 `internal/api/logs.go`**

```
GET /api/hosts/{id}/logs/sources              → handleLogSources
GET /api/hosts/{id}/logs?source=&file=&unit=&priority=&lines=   → handleHostLogs
GET /api/panel/logs?lines=                    → handlePanelLogs
```

- 前两条走 `s.execEscalated(ctx, hostID, script, 15s, escalatePreferred)`：能提权就以 root 跑（`auth.log`/`kern.log`、`journalctl` 系统日志、`dmesg` 在 `dmesg_restrict=1` 时都需要 root），提不了就按普通用户跑、结果里带着 `Permission denied` 如实展示。`hostID = 0`（宿主机）由 `execOnHost` 落到本机执行。
- 返回结构 `{ source, lines, truncated, permissionNote? }`：按行切分；结尾若出现 `Permission denied` / `Operation not permitted` 原文，额外给 `permissionNote`，界面提示"该来源需要 root，当前主机无法提权"。
- `handlePanelLogs` 是**纯本地文件读**：读 `cfg.DataDir/panelssh.log` 的最后 N 行（Seek 到 size-512KiB 再按行切，取尾部 N 行），不经过 SSH。文件不存在时返回空列表 + `note: "面板日志尚未产生"`。

### 前端

**新增 `web/src/windows/LogWindow.vue`**

- 顶部：[HostPicker](file:///media/yunxi/FE73-D3B5/Panel%20SSH/web/src/components/HostPicker.vue)（`includeLocal`，宿主机默认选中）+ 行数选择（100/200/500）+ 自动刷新开关 + 手动刷新。
- 来源用 `NTabs`：`journalctl` / `日志文件` / `dmesg` / `面板日志`。
  - `journalctl`：可选 unit 与优先级（下拉，`api.logs.sources()` 拿到的信息 + 固定优先级列表）。
  - `日志文件`：左侧文件列表（路径、大小、修改时间），选中后右侧显示尾部内容。
  - `dmesg`：直接展示。
  - `面板日志`：**不依赖主机选择**（面板自己的日志），独立拉 `/api/panel/logs`；这条 tab 打开时才请求，并提示"面板重启后日志会轮转"。
- 内容区：`<pre>` 等宽展示，保留换行；顶部一个关键字输入框做**本地过滤 + 高亮**（先对行做 HTML 转义再包 `<mark>`，避免日志内容被当成 HTML 渲染）。
- 自动刷新：`useVisiblePoll`，间隔 5000 ms，`enabled = 已选主机 && 已选来源`；不加后端缓存（200 行文本、5 秒一次，成本可接受；若后续发现多窗口重复采集再引入 `sampleBuffer`）。
- 权限提示条：后端给的 `permissionNote` 非空时在内容区上方显示 `n-alert`。

**注册与图标（与模块一同样的四处）**

- [Desktop.vue](file:///media/yunxi/FE73-D3B5/Panel%20SSH/web/src/desktop/Desktop.vue#L50-L166)：`registry.logs = LogWindow`，`builtinApps` 加 `{ key: 'logs', name: '系统日志', rail: 'var(--app-logs)', multi: true, size: { w: 1180, h: 700 } }`（不同主机的日志要能并排看，与网络/存储一致开多窗口）。
- `AppGlyphs.vue`：加 `<symbol id="glyph-logs">`，用老大给的那段 SVG（方框 + 行 + 缩进块）。
- `tokens.css`：新增 `--app-logs`。
- `client.ts` 新增 `api.logs`（`sources(hostId)` / `tail(hostId, query)` / `panel(lines)`）与对应类型。

## 风险与注意

- `EnvOp.SnapshotDir` 带 `json:"-"`，**不要为了让前端拿到路径而改这个 tag**（它是服务端磁盘路径，不该下发）；一律通过新的 `snapshotView` 暴露布尔与统计值。
- `packages.tsv` 的列格式按包管理器不同（apt 带 `Status-Abbrev`、rpm 是 `name/version/arch`、apk 是整行文本），因此**必须**经 `env.NewManager(profile).ParsePackages` 解析，不能在前端按 `\t` 硬切。
- 日志命令的参数全部来自用户输入，**校验不通过就 400**，不做转义后拼接的"宽容"处理。
- 面板日志落盘会新增一个 `data/panelssh.log`：`.gitignore` 里已有 `data/` 与 `*.log`，无需改动。
