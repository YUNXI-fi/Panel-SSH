# 应用适配规范

本文是 Panel SSH 应用中心的统一适配依据。新增应用、修改应用包、调整图标或界面配置时，都以本文为准。

## 1. 适用范围

Panel SSH 的应用分两层：

| 层级 | 内容 | 是否由本文约束 |
| --- | --- | --- |
| 软件安装 | 由「系统组件 / 软件环境」通过 apt、dnf、yum、apk 或官方源安装 | 否，走环境管理流水线 |
| 应用适配 | 把已安装软件包装成面板里的通用应用窗口：动作、图标、界面分组、配置文件入口 | 是 |

应用适配**不负责安装软件本体**。「系统组件 / 网络安全」卡片上的「面板视图」只安装应用包（元数据、图标、界面配置、动作声明）；目标机上的软件仍需在同一张卡片的「安装」里完成。两层入口放在一起，但状态与按钮分开，避免用户以为点了应用包就已经装好软件。

## 2. 目录结构

```
apps/
├── index.json                 # 应用索引（由生成器维护，不手写）
├── _template/                 # 模板与草稿目录，不进入索引
│   ├── app.json
│   ├── ui.json
│   ├── icon.svg
│   └── README.md
└── <slug>/                    # 每个应用一个独立文件夹
    ├── app.json               # 必需：元数据、动作、配置路径
    ├── ui.json                # 必需：通用窗口布局
    ├── icon.svg               # 必需：应用图标
    └── config/                # 可选：随包分发的配置模板
        └── <name>.template
```

约束：

- 文件夹名必须等于 `app.json` 里的 `slug`。
- `slug` 只允许小写字母、数字与连字符，正则 `^[a-z0-9][a-z0-9-]{0,31}$`。
- 禁止在 `apps/` 根目录平铺文件（`index.json` 除外）。
- `_` 开头的文件夹是模板/草稿，不进入索引、不出现在应用中心。
- 应用包只放声明式资源，禁止放二进制、压缩包、私钥、口令或目标机配置的完整副本。

## 3. 适配流程

1. **盘点**：确认软件在 `internal/env` 的软件目录里有条目（分类、说明、检测命令、服务单元、配置路径）。
2. **建包**：复制 `apps/_template/` 为 `apps/<slug>/`，修改 `app.json`、`ui.json`、`icon.svg`。
3. **声明动作**：把面板要提供的操作写成命令模板，标注 root、超时、确认文案与危险等级。
4. **生成索引**：在 `Panel SSH` 模块目录执行 `go run ./cmd/appgen -out ../apps`。
5. **校验**：执行 `./scripts/validate-apps.sh`，校验摘要、字段、图标规格与资源完整性。
6. **本地验收**：用本地源启动面板，安装应用包，逐个动作执行。
7. **提交**：索引、包文件、生成器改动、文档改动一起提交；索引与包文件必须来自同一次生成。

## 4. app.json

示例：

```json
{
  "schemaVersion": 1,
  "slug": "nginx",
  "name": "Nginx",
  "version": "1.0.0",
  "category": "service",
  "description": "Web 服务器与反向代理",
  "useCase": "静态站点、反向代理与 TLS 终止",
  "note": "启停会中断正在处理的请求",
  "icon": "icon.svg",
  "defaultAction": "status",
  "config": [
    { "path": "/etc/nginx/nginx.conf" },
    { "path": "/etc/nginx/conf.d", "isDir": true }
  ],
  "actions": [
    {
      "id": "status",
      "label": "服务状态",
      "group": "inspect",
      "timeoutSec": 30,
      "command": "systemctl status nginx --no-pager"
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schemaVersion` | 是 | 当前固定为 `1`，不兼容时面板直接拒绝加载 |
| `slug` | 是 | 与文件夹同名，全局唯一 |
| `name` | 是 | 应用中心与桌面显示名 |
| `version` | 是 | 应用包版本（不是软件版本），用于判断更新 |
| `category` | 是 | `security` / `service` / `database` / `monitor` / `toolchain` / `runtime` / `utility` / `network` / `backup` |
| `description` | 是 | 一句话说明"它是什么" |
| `useCase` | 否 | "通常拿来干什么"，与 description 互补 |
| `note` | 否 | 安装、启停或配置时的注意事项 |
| `icon` | 是 | 必须是包内相对路径，当前统一 `icon.svg` |
| `defaultAction` | 否 | 打开窗口时自动执行的动作 id；留空取第一个动作 |
| `config` | 否 | 可在面板里编辑的配置文件/目录；路径必须是绝对路径或 `~/` 开头 |
| `actions` | 是 | 至少一个动作 |

### 4.1 动作（actions）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 小写字母、数字、连字符；`ui.json` 用它引用动作 |
| `label` | 是 | 按钮文案 |
| `description` | 否 | 动作说明，显示在表单标题旁 |
| `group` | 否 | `inspect`（只读诊断）/ `manage`（改变系统状态），默认 `inspect` |
| `fields` | 否 | 表单字段；有字段时点击按钮先弹表单 |
| `confirm` | 否 | 执行前的二次确认文案 |
| `danger` | 否 | 危险动作，按钮标红并强制归入管理操作 |
| `needRoot` | 否 | 需要提权；面板复用主机已配置的 sudo/su 凭据 |
| `timeoutSec` | 否 | 超时秒数，默认 60，上限 1800 |
| `command` | 与 `builtin` 二选一 | 命令模板，支持 `{{field}}` 占位符 |
| `builtin` | 与 `command` 二选一 | 复用面板编译期实现的同名动作（如 GnuPG 密钥生成） |

### 4.2 字段（fields）

| 字段 | 说明 |
| --- | --- |
| `key` | 占位符名；小写字母、数字、连字符 |
| `label` | 表单标签 |
| `type` | `text` / `number` / `select` / `password` / `textarea` |
| `default` | 默认值 |
| `options` | `select` 的可选值 |
| `required` | 是否必填 |
| `help` | 字段下方的说明 |
| `pattern` | Go RE2 正则；非空时校验参数格式 |
| `maxLen` | 最大字节数，默认 200 |

### 4.3 命令模板

- 占位符写作 `{{key}}`，只能引用本动作已声明的字段。
- **参数统一由面板加 shell 单引号**，包作者不要自己给占位符加引号。
- 模板里不能出现未闭合的 `{{` / `}}`。
- 模板是固定命令 + 参数占位，不允许从远端拼接额外命令。
- 需要多步编排、临时文件或口令文件时，用 `builtin: true` 复用面板内置动作，不要尝试用模板模拟。
- `needRoot` 为真时，面板会走统一提权链路；不要自己写 `sudo` / `su`。

### 4.4 builtin 动作

`builtin: true` 的动作只写 `id` 与展示元数据，执行时使用面板编译期实现。适用于：

- GnuPG 的生成/导入/删除（需要临时参数文件与 passphrase）；
- 需要结构化结果或复杂状态解析的动作；
- 不能安全地用一条 shell 模板表达的动作。

内置动作的可用 id 以 `internal/api` 的动作目录为准。包内声明 builtin 但面板没有对应实现时，该动作会被忽略。

## 5. ui.json

```json
{
  "schemaVersion": 1,
  "layout": "generic",
  "overview": ["status"],
  "sections": [
    { "title": "查看与诊断", "actions": ["version", "status", "logs"] },
    { "title": "管理操作", "actions": ["start", "restart", "stop"] }
  ],
  "hint": "服务由 systemd / OpenRC 托管；启停会改变主机状态。"
}
```

- `layout` 当前固定 `generic`，对应面板的通用应用窗口。
- `overview` 预留：打开窗口时可自动执行的动作 id；当前以 `defaultAction` 为准。
- `sections` 决定侧栏分组与顺序；引用不存在的动作会被忽略。
- `hint` 显示在侧栏底部，说明该应用的执行口径与风险。

## 6. 图标标准

| 项 | 规范 |
| --- | --- |
| 格式 | SVG（推荐）或 PNG |
| 文件名 | `icon.svg`；PNG 回退为 `icon.png` |
| 画布 | SVG 必须 `viewBox="0 0 24 24"` |
| 颜色 | 使用 `currentColor`，由面板按主题与身份色着色 |
| 线宽 | 线性图标统一 `stroke-width="1.6"`，圆角端点 |
| 留白 | 图形控制在 2–22 的坐标范围内，避免贴边裁剪 |
| 尺寸 | 桌面上按 22×22、窗口标题 17×17、文件夹缩略 11–16×16 渲染；矢量缩放，不另存多套 |
| PNG | 如必须提供，使用 256×256，透明背景，文件名 `icon.png` |
| 安全 | 不引用外部资源、不写脚本、不使用 `<image>` 外链 |

网络安全类应用沿用面板已有的 15 个线性图标；其余应用由生成器输出「圆角方框 + 两位字母」的统一图标。新增图标必须与现有图标同一视觉密度，不引入写实或多色风格。

## 7. 配置文件

- `config` 中的路径是**目标机上的路径**，不是仓库里的路径。
- 文件路径必须是绝对路径或以 `~/` 开头；目录项用 `isDir: true`。
- 面板保存前会 `cp -p` 备份为 `<path>.panelssh.bak`，再原子替换。
- `/etc` 下默认用 root；`~` 与 `/home/` 下按登录用户执行。
- 仓库里的 `apps/<slug>/config/` 只放**模板**（如 `*.template`），不得放真实口令、私钥、证书私钥或目标机导出的完整配置。

## 8. 应用中心拉取与更新

- 默认索引地址：`https://raw.githubusercontent.com/YUNXI-fi/Panel-SSH/main/apps/index.json`
- 应用中心页签行最右侧的齿轮可以改仓库源：保存前会试拉一次索引，源不可用时保留原地址；地址保存在数据库，优先于环境变量。
- `PANELSSH_APP_INDEX_URL` 用于部署期指定默认源；`PANELSSH_APP_SOURCE_DIR` 指向本地目录做离线/测试。
- 面板缓存索引 10 分钟；「系统组件 / 网络安全」页签可点「刷新视图」强制拉取。
- 拉取失败时退回本地缓存，界面标记「本地缓存」。
- 安装/更新流程：拉取索引 → 逐文件下载 → 校验 SHA-256 → 写入临时目录 → 整体替换 → 记录桌面入口。
- 卸载只删除面板本地应用包与桌面入口，不碰目标机上的软件和配置文件。
- 更新判断：索引版本 > 已安装版本。版本号建议使用 `主.次.修订`。

## 9. 验收标准

每个应用包必须同时满足：

- [ ] `go run ./cmd/appgen -check -out ../apps` 通过。
- [ ] `./scripts/validate-apps.sh` 通过。
- [ ] 应用中心能展示名称、说明、分类、版本与图标；图标不空白、不变形。
- [ ] 「安装」后桌面出现带图标的入口；窗口标题与图标一致。
- [ ] 默认动作能在目标机执行并返回结果；失败时能看到错误输出。
- [ ] 每个带字段的动作都能提交表单；非法参数被后端拒绝。
- [ ] 需要 root 的动作在无提权方式的主机上给出明确提示，而不是静默失败。
- [ ] 配置文件能读取、编辑、保存；保存后生成 `.panelssh.bak`。
- [ ] 目录型配置为只读浏览，不出现「保存」按钮。
- [ ] 更新：索引版本提升后应用中心显示「可更新」，更新后版本与文件摘要一致。
- [ ] 卸载后桌面入口消失，重新安装可恢复。
- [ ] 包内没有二进制、私钥、口令或测试数据。

## 10. 安全约束

- 应用包来自固定 HTTPS 源，索引内带每个文件的 SHA-256；校验失败不落盘。
- 命令模板只能使用声明过的字段，参数由面板统一加引号，包作者不能绕过。
- 远程包不携带可执行文件；需要复杂逻辑时使用 builtin 动作。
- 安装、更新、卸载都需要管理员在应用中心显式操作。
- 任何涉及密钥、口令的动作不得把敏感值写入命令参数或日志。

## 11. 新增应用检查清单

1. 软件条目存在，检测命令可用。
2. `app.json` 与文件夹同名，字段齐全。
3. 动作覆盖"看状态、看版本、必要的管理操作"，没有把整段终端命令直接暴露给用户。
4. `ui.json` 分组与实际动作一致。
5. 图标符合 24×24 / currentColor 标准。
6. 配置路径只包含确实需要编辑的文件与目录。
7. 生成索引并校验通过。
8. 在至少一台宿主机和一台远端主机上完成安装、执行、配置、卸载验收。
